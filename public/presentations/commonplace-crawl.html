How it works

  1. 01

    Build the taste profile

    Pull the community summaries from the library’s ChromaDB store. Claude names the clusters whose summaries had generic headings, once, and the names are cached.

  2. 02

    Crawl with one Kernel browser

    A stealth-mode Kernel browser opens each magazine’s index, keeps links that look like articles, then reads them four tabs at a time. It checks robots.txt first and waits out any crawl delay, like Lapham’s ten seconds.

  3. 03

    Embed and match

    Each article’s title, description and opening paragraphs are embedded with the same model as the library, then compared with every cluster.

  4. 04

    Explain the pick

    The closest cluster becomes the reason, with the books that anchor it. Only links and short descriptions are kept, never full articles.

# The Kernel part is small: create a browser, attach Playwright over CDP.
kb = kernel.browsers.create(stealth=True)
browser = await p.chromium.connect_over_cdp(kb.cdp_ws_url)
page = browser.contexts[0].pages[0]
await page.goto(site, wait_until="domcontentloaded")
...
kernel.browsers.delete_by_id(kb.session_id)

What broke along the way

Both bugs looked like bot detection. Neither was.

The Paris Review came back nearly empty

245 characters from a page with 13 articles. My cleaner deleted every <header> to remove site navigation, but the magazine puts each article’s title inside one. Removing only headers outside <main> and <article> brought back the full page.

Four magazines returned zero links

Python’s robots.txt parser treats a 403 as “disallow everything,” and these sites return 403 to Python’s default user agent. Their actual robots.txt files allow crawling. Fetching the file with a normal client fixed it.
